# ACCEPTANCE_CRITERIA.md Schema (v1)

Structured YAML frontmatter consumed by `scripts/_audit_gates.py`, `compare_with_autosota.py`, and `post_exp_insights.py`. The orchestrator uses these fields to compute verdicts; subagents cannot waive them at execution time.

## Contract

Every `plan/ACCEPTANCE_CRITERIA.md` generated by `/paper-to-plan` begins with a YAML block delimited by `---`. The block conforms to `schema_version: 1`. Below it, the rest of the file is human-readable prose. Orchestrator reads only the frontmatter; humans and subagents may read both.

## Fields (all generic — no domain-specific names)

```yaml
---
schema_version: 1

primary_metric:
  name: <metric_id>              # free string, must match keys in our_results.metrics
  direction: maximize | minimize # which direction counts as improvement
  unit: ratio | percent | absolute | score
  theoretical_max: <number|null> # null if the metric is unbounded
  saturation_bound: <number|null># often 0.99 * theoretical_max; triggers G_SATURATION
  min_detectable_delta: <number> # absolute Δ below which a claim is within noise

eval_splits: [<split_id>, ...]   # every split the paper requires be reported
dev_split: <split_id|null>       # where hyperparameter / threshold selection is allowed
report_split: <split_id>         # the split whose value enters the verdict

guards:                          # auxiliary claims; enforced by the orchestrator
  - name: <guard_id>
    metric: <metric_id>
    split: <split_id|any>
    op: ">=" | "<=" | ">" | "<" | "=="
    threshold: <number>
    severity: hard | soft        # hard fail -> verdict forced to 'below'

resource_budget:
  gpu_hours: <float>
  wallclock_hours: <float|null>

sweep_budget:
  max_trials: <int>              # configs on the eval set allowed across the whole run
  max_seeds_per_trial: <int>
  max_ensemble: <int>            # ensemble size ceiling
  parity_ratio_vs_reference: 1.25 # our / reference must stay under this

statistics:
  min_seeds: <int>               # N independent runs for CI on primary metric
  ci_method: bootstrap | seed_std | none
  ci_level: 0.95

heldout:                         # OPT-IN independent verification (Phase 1). Omit to disable.
  required: true | false         # if true, a BEAT requires an INDEPENDENT held-out result
  split: <split_id>              # the split the independent runner re-evaluates (held-out; agent-unwritable)
  mismatch_tolerance: <number|null> # |self_report - independent| on report_split beyond this = overfit flag
                                 #   (default: primary_metric.min_detectable_delta)
---
```

## What the orchestrator does with this

| Gate | Reads | Enforces |
|---|---|---|
| `G_ACCEPTANCE_GUARDS` | `guards[]` | every `severity: hard` must pass; `soft` only warns. Hard fail → verdict forced to `below` regardless of primary metric |
| `G_SIGNIFICANCE` | `primary_metric.min_detectable_delta`, `statistics.min_seeds` | Δ over reference must exceed `max(ci_half_width, min_detectable_delta)`; n_seeds ≥ `min_seeds` OR explicit CI present, else `unknown` |
| `G_RESOURCE_PARITY` | `resource_budget`, `sweep_budget`, `our_results.resources` | our axes ≤ reference × `parity_ratio_vs_reference` |
| `G_EVAL_HYGIENE` | `eval_splits`, `dev_split`, `our_results.selection_split`, `our_results.split_scores` | selection must be on `dev_split` (never on any `eval_split`); all `eval_splits` must be reported |
| `G_SATURATION` | `primary_metric.saturation_bound`, `our_results.split_scores` | if observed ≥ bound, require a corroborating split whose score < bound |
| `G_HELDOUT_MERGE` | `heldout.{required,split,mismatch_tolerance}`, `our_results.heldout` | **only when `heldout.required`.** The candidate's INDEPENDENTLY re-computed held-out score (written by `scripts/heldout_eval.py`, never by the executor) must clear the noise floor over the reference. A self-report optimistic beyond `mismatch_tolerance`, or an eval-harness tamper, forces `pending_gate`. Missing independent result on a would-be BEAT → `pending_gate`. |

A would-be BEAT that trips any gate is automatically downgraded to MATCH (or BELOW if a hard guard fails). A would-be BEAT with any `unknown` gate becomes `pending_gate` and flips STATE's `pending_gate.needs_user = true`.

## Three generic examples

### A. Classification accuracy (bounded, maximize)

```yaml
---
schema_version: 1
primary_metric:
  name: accuracy
  direction: maximize
  unit: ratio
  theoretical_max: 1.0
  saturation_bound: 0.99
  min_detectable_delta: 0.003
eval_splits: [test]
dev_split: val
report_split: test
guards:
  - { name: calibration_ece, metric: ece, split: test,
      op: "<=", threshold: 0.05, severity: hard }
  - { name: worst_group_floor, metric: accuracy, split: worst_group,
      op: ">=", threshold: 0.70, severity: hard }
resource_budget: { gpu_hours: 12.0, wallclock_hours: null }
sweep_budget: { max_trials: 24, max_seeds_per_trial: 3, max_ensemble: 5,
                parity_ratio_vs_reference: 1.25 }
statistics: { min_seeds: 3, ci_method: bootstrap, ci_level: 0.95 }
---
```

### B. Regression MSE (unbounded, minimize)

```yaml
---
schema_version: 1
primary_metric:
  name: mse
  direction: minimize
  unit: absolute
  theoretical_max: null
  saturation_bound: null
  min_detectable_delta: 0.0005
eval_splits: [test_clean, test_ood]
dev_split: null                 # paper has no dev split; sweep must be a priori
report_split: test_clean
guards:
  - { name: ood_not_worse, metric: mse, split: test_ood,
      op: "<=", threshold: 0.42, severity: hard }
resource_budget: { gpu_hours: 4.0, wallclock_hours: 2.0 }
sweep_budget: { max_trials: 3, max_seeds_per_trial: 3, max_ensemble: 1,
                parity_ratio_vs_reference: 1.25 }
statistics: { min_seeds: 3, ci_method: seed_std, ci_level: 0.95 }
---
```

### C. Inference speedup (ratio, maximize, unbounded)

```yaml
---
schema_version: 1
primary_metric:
  name: speedup_ratio
  direction: maximize
  unit: ratio
  theoretical_max: null
  saturation_bound: null
  min_detectable_delta: 0.02
eval_splits: [bench_public]
dev_split: null
report_split: bench_public
guards:
  - { name: output_quality, metric: quality_score, split: bench_public,
      op: ">=", threshold: 0.95, severity: hard }   # no quality regression
  - { name: wall_budget, metric: end_to_end_latency_sec, split: bench_public,
      op: "<=", threshold: 60, severity: soft }
resource_budget: { gpu_hours: 2.0, wallclock_hours: null }
sweep_budget: { max_trials: 6, max_seeds_per_trial: 1, max_ensemble: 1,
                parity_ratio_vs_reference: 1.25 }
statistics: { min_seeds: 1, ci_method: none, ci_level: 0.95 }
---
```

## `our_results.json` contract additions

`/plan-to-experiment` must emit these fields so the gates have signal:

```json
{
  "primary_metric": "<same id as frontmatter>",
  "metrics": {
    "<metric_id>": {
      "value": <number>,
      "ci_lower": <number|null>,
      "ci_upper": <number|null>,
      "n_seeds":  <int|null>
    }
  },
  "split_scores": {
    "<split_id>": { "<metric_id>": <number>, "...": ... }
  },
  "selection_split": "<split_id>",
  "resources": {
    "gpu_hours": <float>,
    "sweep_trials": <int>,
    "seeds": <int>,
    "ensemble_size": <int>
  },

  "heldout": {                     // ADVISORY copy only. The gate's AUTHORITATIVE source is the
                                   // coordinator-owned HELDOUT_RESULT.json (heldout_eval.py --result-out);
                                   // compare_with_autosota --heldout-result overrides/drops this copy, so
                                   // a forged heldout block in results.json is ignored.
    "produced_by": "independent_runner",
    "split": "<split_id>",
    "metrics": { "<metric_id>": <number> },
    "candidate_commit": "<git sha>",
    "eval_harness_sha": "<sha over the eval files actually used>",
    "tamper_ok": true,             // false if eval files diverged from HELDOUT_LOCK
    "env_hash": "<env fingerprint|null>"
  }
}
```

Any missing field degrades the relevant gate to `status: unknown` rather than crashing — and unknown on a would-be BEAT triggers `pending_gate`. The `heldout` block is consumed by `G_HELDOUT_MERGE` only when the frontmatter sets `heldout.required: true`; otherwise that gate is `n/a`.

## Migration

Legacy plans without frontmatter still work: `post_exp_insights.py` falls back to a regex scraper for the "Min pass / Ideal / Fail" headings, but no integrity gates fire. To enable gates, re-run `/paper-to-plan` with `schema_version: 1` or hand-migrate the frontmatter.
